# Seatly — бронирование рабочих пространств

Поиск помещений и бронирование временных интервалов: заявка гостя, подтверждение владельцем, перенос и отмена.

## Возможности

- Поиск, фильтры района, типа и вместимости, избранное и фотографии помещений.
- Серверный расчёт цены, удержание интервала на 30 минут, подтверждение, перенос и отмена.
- Аккаунты гостя и владельца, cookie-сессии, приватные списки бронирований и постраничное API.

## Стек и устройство

React, TypeScript, Vite, Express, Zod и встроенный SQLite в Node.js. Изображения включены в сборку и загружаются с того же сервера.

## Ключевые решения

- `server/app.ts` получает блокировку `BEGIN IMMEDIATE` до чтения ключа идемпотентности, вместимости и цены. Бронирование и сохранённый ответ повторного запроса фиксируются вместе.
- Триггеры INSERT/UPDATE запрещают пересечение активных интервалов; соседние интервалы разрешены. Проверяются отдельные HTTP-процессы с подключениями к одному SQLite-файлу.
- `server/booking-constraints.sql` отклоняет некорректные даты, интервалы, превышение вместимости и неположительные цены активных бронирований. Исторические записи не переписываются.
- Стоимость вычисляется из сохранённой цены помещения и длительности. Клиент не задаёт итоговую сумму. Владение бронью и право подтверждения проверяются на сервере.
- Опубликованные локальные аккаунты доступны только на loopback вне production; Host/Origin проверяются. Пароли используют scrypt; случайные токены сессий хранятся как SHA-256-хеши, cookie имеют HttpOnly/SameSite=Strict, выход отзывает сессию.

## Локальный запуск

Node.js 24.18.0 и pnpm 11.7.0; версии закреплены в файлах проекта.

```bash
npm install --global pnpm@11.7.0
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

Откройте `http://localhost:4200`. Сервер по умолчанию слушает 127.0.0.1. Для разработки доступен `pnpm dev`.

## Настройки

Параметры перечислены в [.env.example](.env.example). `pnpm start` использует окружение процесса и не загружает файл автоматически. После копирования `.env` его можно загрузить явно: `node --env-file=.env --import tsx server/index.ts`.

## Данные и обновления

SQLite хранится в `data/seatly.db`. Инициализация создаёт или обновляет схему. Перед обновлением сохраните резервную копию; удалять БД вместо миграции не нужно.

## Проверки

```bash
pnpm lint
pnpm format:check
pnpm test
pnpm test:contract
pnpm test:upgrade
pnpm typecheck
pnpm build
pnpm exec playwright install chromium firefox webkit
pnpm test:e2e
pnpm audit --audit-level=high
```

Проверяются конкурирующие бронирования и повторные ключи, валидация на уровне SQL, откаты, очистка по управляемым часам, блокировка вторым подключением, повтор после 503, сохранение сессий после перезапуска, переносы, резервные копии и браузерные сценарии.

CI устанавливает зависимости по зафиксированным версиям и запускает настроенные проверки. Отдельная проверка документации находит неверные локальные ссылки и изображения. Проверка уязвимостей учитывает известные проблемы на момент запуска.

## Ограничения

- Опубликованные аккаунты относятся к локальному режиму. В production и при внешнем HOST сервер прекращает запуск до открытия БД. Для работы с реальными клиентами нужна отдельная выдача аккаунтов и настройка защищённого размещения.
- Время задано в фиксированной московской зоне UTC+03:00; нескольких зон и DST нет. Стоимость округляется до целых рублей, платежи не подключены.
- Просроченные удержания освобождаются перед операциями API, при запуске и таймером каждые 30 секунд. Таймер идемпотентен и останавливается при завершении; корректность записи не зависит от точности его срабатывания.
- Прямые SQL-клиенты должны вызывать общую очистку перед выделением слота. SQLite имеет одного писателя и busy timeout 5 секунд; при временной конкуренции возвращается 503 без частично использованного ключа запроса.
- Адаптер размещённой версии D1 выпускается отдельно. Браузерная версия сохраняет данные на устройстве.
