# Seatly — бронирование рабочих пространств

Выбор помещения, заявка на бронирование, подтверждение владельцем и отмена.

**Статус:** Самостоятельный портфолио-проект. Проект использовался реальными пользователями. Публикуется демонстрационная версия, без заявлений о масштабе или коммерческих показателях.

![CI](https://github.com/memorim/seatly-workspace-booking/actions/workflows/ci.yml/badge.svg)

[Браузерное демо](https://memorim.github.io/seatly-workspace-booking/) · [Разбор проекта](docs/CASE_STUDY.md) · [Видео: около минуты](docs/walkthrough.webm)

Локальный API: `http://localhost:4200`. Демо-аккаунты: `guest@seatly.example` / `GuestDemo2026!` и `owner@seatly.example` / `OwnerDemo2026!`. Это специально опубликованные учебные реквизиты, не личные аккаунты.

GitHub Pages сохраняет данные только в браузере посетителя. Это отдельная сборка с localStorage, без общего сервера. Переключение демонстрационных участников в ней не является аутентификацией.

## Что работает
- Поиск по названию и району, фильтры по типу и вместимости, избранное.
- Будущая дата, время по Москве, доступность, цена с точностью до минуты.
- Серверные сессии, кабинеты гостя и владельца, личный список бронирований.
- Заявка → ожидание → подтверждение или отмена; отмена освобождает интервал.
- Адаптивные формы, загрузка, ошибки с повтором и пустые результаты.

## Запуск и проверка
Node.js 24, pnpm 11. Стек: React, TypeScript, Vite, Express, SQLite, Zod.

```bash
pnpm install --frozen-lockfile
pnpm test
pnpm typecheck
pnpm exec playwright install chromium
pnpm test:e2e
pnpm build
pnpm start
```

## Технические решения
- `BEGIN IMMEDIATE` и триггеры SQLite защищают от пересечений при записи, включая прямой SQL и другие соединения. Соседние интервалы разрешены.
- Pending и confirmed занимают место; cancelled не участвует в проверке.
- Цена и владелец заявки определяются сервером. Гость не видит и не отменяет чужие заявки.
- Пароли хешируются scrypt; непрозрачные сессии хранятся по SHA-256, cookie HttpOnly/SameSite; выход отзывает сессию.

## Границы готовности
- Два публичных демонстрационных аккаунта; регистрации, восстановления пароля и реальных платежей нет.
- Каталог, рейтинги и исходные заявки — вымышленные примеры. Старые заявки без user_id видны владельцу.
- Серверная сборка предназначена для локальной демонстрации. Перед публичной эксплуатацией нужны реальные аккаунты, TLS, общий лимитер входа, резервные копии и эксплуатационный мониторинг.
- GitHub Pages не синхронизирует бронирования между посетителями.
