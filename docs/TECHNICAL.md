# Устройство Seatly

## Запуск
Node.js 24, pnpm 11. `pnpm install --frozen-lockfile`, `pnpm build`, `pnpm start`. Интерфейс и API работают на одном origin, порт 4200. Режим разработки: `pnpm dev`.

SQLite хранится в `data/seatly.db`, каталог создаётся автоматически. Не удаляйте его для обновления. Добавление user_id, expires_at, таблиц пользователей и сессий выполняется совместимо при старте; старые записи сохраняются.

## Контракт
- POST /api/login — email/password; сервер устанавливает HttpOnly cookie.
- GET /api/session; POST /api/logout.
- GET /api/spaces; GET /api/spaces/:id/availability?date=YYYY-MM-DD — только интервалы, без контактов.
- GET /api/bookings — свои заявки; владельцу доступны все.
- POST /api/bookings — spaceId, guestName, guestEmail, bookingDate, startTime, endTime, guests. Ответ 201; пересечение 409; ошибка хранения 503.
- PATCH /api/bookings/:id/confirm — только владелец, pending → confirmed.
- DELETE /api/bookings/:id — отмена, повторная отмена существующей заявки возвращает 204.

Время бронирования — Москва. Pending и confirmed блокируют интервал. Триггеры проверяют пересечение по строгим неравенствам; окончание предыдущего в момент начала следующего разрешено. BEGIN IMMEDIATE захватывает блокировку записи до вставки, WAL и busy_timeout уменьшают конфликты читателей/писателей.

Ограничения: публичные учебные аккаунты, нет регистрации, оплаты и уведомлений. Ограничитель входа хранится в памяти процесса. Это локальный серверный пример, не готовый коммерческий сервис.


Перенос: PATCH /api/bookings/:id/reschedule принимает bookingDate, startTime, endTime, guests. Пересчёт и смена слота атомарны; успешный перенос снова pending на 30 минут, конфликт 409 сохраняет старую запись. Истечение pending обрабатывается при следующем API-запросе; cancelled/expired не занимают слот.

Онлайн-сборка: `/seatly/index.html`, API `/api/seatly`. Вход выполняет Sites. D1 хранит отдельные площадки по хешу доверенной site identity; смена учебной роли не меняет площадку. Учебная модель специально позволяет одному посетителю пройти обе роли. Node-сессии и их общие публичные пароли не используются в размещённой версии. До 200 заявок на площадку; это демонстрация без реальных услуг.

## Текущий режим работы
Node API использует сессии и два публичных аккаунта для просмотра ролей: guest@seatly.example / GuestDemo2026! и owner@seatly.example / OwnerDemo2026!. Это опубликованные реквизиты примера. Вход размещённой версии — через ChatGPT; у посетителя отдельная площадка в D1 с переключением двух ролей. GitHub Pages хранит записи в одном браузере. Регистрация, восстановление пароля и платежи требуют отдельных интеграций. Старые заявки без user_id доступны владельцу. Автоматические копии SQLite относятся только к работающему Node-серверу; D1 обслуживается отдельно.
