# Seatly: от каталога до подтверждённого бронирования

## Задача и мой вклад
Самостоятельно разработанный портфолио-проект выбора и бронирования помещений. Проект использовался реальными пользователями; здесь показан демонстрационный вариант.

Работа охватывает интерфейс, адаптивную вёрстку, REST API, SQLite, модель прав и проверки. Цель текущего этапа — провести пользователя через законченный сценарий, а не оставить карточки как макет.

## Пользовательский путь
Каталог → тип/вместимость/избранное → дата и интервал → вход → заявка pending → подтверждение владельцем → личный список → отмена. Невозможный интервал, чужая заявка, занятость и сбой API обрабатываются отдельными ответами.

## Решения
1. SQLite подходит для компактного локального примера: не нужен отдельный сервер БД. BEGIN IMMEDIATE и триггеры защищают запись от конкурирующего бронирования; проверка только в React не обеспечила бы это.
2. Pending резервирует место сразу. Иначе несколько гостей могли бы ожидать подтверждения одного интервала. Отмена снимает резерв; pending истекает через 30 минут. Очистка выполняется при API-запросе, отдельного фонового процесса нет.
3. Минимальные серверные сессии используют scrypt, случайный токен и хранение его хеша. Гость получает только свои записи; owner подтверждает. Регистрация и восстановление не включены в демонстрацию.
4. Статическое демо изолировано от Node API: удобно посмотреть интерфейс без установки, но нельзя выдавать localStorage за совместную работу.

## Подтверждение
API-тесты проверяют пересечения, соседние интервалы, дробную цену, права и отзыв сессии. Проверка прямой вставки SQL подтверждает защиту в БД. Playwright проводит гостя и владельца в независимых браузерных контекстах, включая мобильный экран, подтверждение, перезагрузку и отмену. Отдельный сценарий проверяет восстановление после 503.
